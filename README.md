# 飞书群消息总结机器人

机器人加入群后会自动收集群内消息。群里发送“打开日报”会立即生成并回复当天日报，也兼容 `#总结` 和 `#今日总结`。

本项目以 MIT 许可证开源。仓库只保存通用代码、脱敏示例和搭建教程；真实群配置、成员身份、数据库和 API 凭据必须留在本地或服务器。

## 工作方式

- 只处理群消息，不处理私聊。
- 自动记录文字、富文本和常见媒体占位信息，不做图片 OCR；图片只计张数。
- 支持话题作业：话题内的图片、文件或视频按发送人记为提交，并保留话题 ID、文件名、消息 ID 和提交时间；普通群文件不自动算作业。
- 将消息中的 @ 占位符还原为群成员昵称，并按昵称保留原始发话时间。
- 合并转发会尽量展开其中可读文字。
- 用 `message_id` 去重，服务重启后不会重复收集。
- 按群、按自然日分别总结；多个群互不混合。
- 多群通过 `GROUP_DATABASES_JSON` 路由到不同 SQLite 文件，从物理存储层隔离消息、打卡状态和发送幂等记录。
- 代码按固定的 22 人名单计算图片作业、当日 `#复盘`、两项均完成及未完成人员，人数和名单不交给模型猜。
- `#复盘` 默认按消息提交日归属；标签后明确写了其他日期（如 `#复盘 0811`）时，不计入 0812 日报。
- MiniMax-M3 只整理每日复盘、群内反馈、方法沉淀和待解决问题。
- 默认无感识别当日图片作业；当天出现 `#MMDD任务已完成`时，自动改按该标签统计。
- 写明“补交/补卡/补打卡”的图片不计入当日作业；`#MMDD复盘`与 `#复盘 MMDD` 均支持。
- 群成员可 `@知识库助手` 查询今天、昨天或 `MMDD` 指定日期的作业、复盘、未交名单与日报；普通群聊和成员之间的 @ 不触发机器人回复。
- 群成员可用 `@知识库助手 补交第2次作业` 或 `@知识库助手 #8月21日 第2次作业已补交` 发起本人补卡核验；身份直接取飞书消息的真实发送人，不要求额外写“我/本人”。机器人只认该发送人的作业链接、图片、文件、话题或完整作业正文，按证据真实时间判定正常/补卡后再写回数据库和多维表格，口头声明不会直接改状态。
- 支持按成员查询全部历史，例如 `@知识库助手 查询小李全部打卡记录`，返回逐次作业、复盘和累计状态。
- 每次生成日报时，会把全员作业/复盘状态和来源消息 ID 写入本地结构化打卡表。
- 同一份状态会自动同步到飞书多维表格，并提供“当前作业周期、本周期已提交、本周期待提交、补卡成员、待迭代、已迭代、本周期已复盘”视图；所有视图都只读取当前周期。
- 打卡表以“作业周期”为主索引，每期包含作业序号和明确起止日期；自然日只用于记录发布、提交和截止时间。
- “周期状态”由机器人自动在“当前周期/历史周期”之间切换，视图固定筛选“当前周期”即可，不再依赖“今天/昨天”。
- 组长可在当期“今日打卡”中修改“人工状态”：正常提交、补卡、未提交或不参与统计。人工列由人维护，机器人不会覆盖。
- “不参与统计”不进入分母、未交名单、催交和群日报；群里不展示该成员姓名、原因或排除人数。
- 技术组从 2026-08-17 开始，每两天为一次作业：第一天 10:00 发布，第二天 20:00 截止；第二天只强化学习，不新增作业。
- 只在每次作业的第二天发送打卡消息：12:00 原生富文本 @ 未交成员，17:00 发送未交名单，20:00 发送最终的已完成/未完成汇总。
- 第二天 20:00 后至第三天 20:00 为补交期；第三天 17:00 @ 仍未交成员，20:00 发“正常提交/已补交/仍未交”汇总，之后仍未交记为旷卡。
- 支持为单次作业设置延期截止时间；延期只影响指定作业，截止前仍算正常提交，截止后才算补卡。
- 带日期作业标签的新提交会立即刷新数据库和多维表格，延期截止后的提交自动记为补卡。
- 只有确实写入作业证据的新消息才会获得随机表情回复：第一天从送心/碰拳/大笑/比心中选，第二天从机智/调皮/了解/击掌/撒花中选，补卡从思考/在做了/惊喜/了解中选；同一消息只回复一次，不回填历史消息。
- 支持 `@知识库助手 @成员 #迭代 DAY5` 记录待迭代，成员用 `@知识库助手 #迭代 DAY5 已完成` 更新为已迭代。
- 多维表格按成员累计正常提交、补卡和旷卡次数；跨日第一次提交或明确补卡才算补卡，优化版不重复计数。
- 群内发送使用飞书原生 `post` 富文本，标题固定为“进阶营作业群・每日日报”，不会发送 Markdown 源文本。
- 每天 23:00 先刷新多维表格，再向各群发送一条只含核心数字和“今日打卡表”链接的飞书原生富文本简报；不调用 MiniMax 生成长文。
- 群内 @ 查询和“打开日报”仍可随时生成完整日报。
- `SUMMARY_SEND_ENABLED=false` 时不会向群内发送任何信息。
- 直接使用飞书开放 API 和机器人拥有的多维表格，不需要小龙虾/OpenClaw。

当前作业周期：第 1 次为 08-17—08-18，第 2 次为 08-19—08-20，第 3 次为 08-21—08-22，以此类推。

当前群路由：27组使用 `data/group_27.sqlite3`，24组使用
`data/group_24.sqlite3` 和独立多维表格。两组共用同一套统计、补卡、@ 查询、

20:00 补交汇总机制；仅成员名单、消息库、发送幂等
记录和多维表格相互独立。

## 本地运行

```bash
cp .env.example .env
# 填写飞书 App Secret 与 MiniMax API Key；名单或打卡表变化时再覆盖 REPORT_* 配置
python3 -m venv .venv
. .venv/bin/activate
pip install -e '.[dev]'
feishu-group-summary doctor
feishu-group-summary run
```

## 飞书设置

应用需要开启机器人能力、使用长连接订阅 `im.message.receive_v1`，并拥有读取群消息、获取群成员、以机器人身份发消息和 `im:message.reactions:write_only` 的权限。修改后必须创建版本并发布，再把机器人加入目标群。详见 [飞书后台配置](docs/飞书后台配置.md)。

## 运维命令

```bash
# 检查飞书凭证与总结模型
feishu-group-summary doctor

# 只预览，不发群
feishu-group-summary summary --date 2026-08-11 --chat-id oc_xxx --dry-run

# 手动发送
feishu-group-summary summary --date 2026-08-11 --chat-id oc_xxx

# 只同步结构化打卡记录，不调用模型，也不向群里发消息
feishu-group-summary sync --from-date 2026-08-11 --to-date 2026-08-16 --chat-id oc_xxx

# 只把数据库中已审核的历史状态重新同步到 Base，不重新判定群消息
feishu-group-summary sync --from-date 2026-08-09 --to-date 2026-08-16 --stored-only
```

服务器部署采用 systemd，单元模板位于 [deploy/feishu-group-summary.service](deploy/feishu-group-summary.service)。
