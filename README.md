# 飞书群消息总结机器人

机器人加入群后会自动收集群内消息。群里发送“打开日报”会立即生成并回复当天日报，也兼容 `#总结` 和 `#今日总结`。

本项目以 MIT 许可证开源。仓库只保存通用代码、脱敏示例和搭建教程；真实群配置、成员身份、数据库和 API 凭据必须留在本地或服务器。

## 工作方式

- 机器人首次进入已配置的新群时，会自动发送一份飞书原生富文本使用指南；SQLite 保存发送记录，服务重启不重发，已有历史消息的群不补发。
- 只处理群消息，不处理私聊。
- 自动记录文字、富文本和常见媒体占位信息，不做图片 OCR；图片只计张数。
- 支持话题作业：话题内的图片、文件或视频按发送人记为提交，并保留话题 ID、文件名、消息 ID 和提交时间；普通群文件不自动算作业。
- 将消息中的 @ 占位符还原为群成员昵称，并按昵称保留原始发话时间。
- 合并转发会尽量展开其中可读文字。
- 用 `message_id` 去重，服务重启后不会重复收集。
- 按群、按自然日分别总结；多个群互不混合。
- 多群通过 `GROUP_DATABASES_JSON` 路由到不同 SQLite 文件，从物理存储层隔离消息、打卡状态和发送幂等记录。
- 代码按固定的 22 人名单计算图片作业、当日 `#复盘`、两项均完成及未完成人员，人数和名单不交给模型猜。
- `#复盘` 默认按消息提交日归属；标签后明确写了其他日期（如 `#复盘 0811`）时，不计入 0812 日报。
- MiniMax-M3 整理每日复盘、群内反馈、方法沉淀和待解决问题，并承担受限的查询意图解析与作业文字点评；人数、名单和状态始终由程序核验。
- 默认无感识别当日图片作业；当天出现 `#MMDD任务已完成`时，自动改按该标签统计。
- 写明“补交/补卡/补打卡”的图片不计入当日作业；`#MMDD复盘`与 `#复盘 MMDD` 均支持。
- 群成员可 `@知识库助手` 查询今天、昨天或 `MMDD` 指定日期的作业、复盘、未交名单与日报；开启群助教对话后，直接 @ 还可以询问群规则、项目卡点和其他低风险普通问题。成员之间的 @ 不触发机器人回复。
- 发 `@知识库助手 菜单` 可查看功能入口，也可 @ 后直接发 `1`—`7` 查进度、未交、我的战绩、补卡、本周成长卡、打卡表或前三次作业复查。这是原生富文本数字菜单，不依赖卡片按钮回调。
- 固定统计问法未命中时，MiniMax 可将“第三次还有哪些人掉队了”这类自然语言收敛为受限查询 JSON，再由数据库计算结果；非统计问题走独立的普通对话路由，不具有改表权限。
- 成员可查 `@知识库助手 我的战绩` 查看累计正常、补卡、未交、复盘和连续准时；发 `@知识库助手 本周成长卡` 按需生成群周战报，不新增自动群发时间。
- 支持只读多周期复查：`@知识库助手 前三次作业`、`第1到3次`、`这三次是否属实`、`技术周整体` 或 `视频周整体`。结果逐期列出正常提交、补卡、最终完成和未交名单，并给出跨期总览；查询只读 SQLite 和多维表格当前状态，不回写数据。
- 交作业时加 `#求反馈`，MiniMax 只根据该条消息里的作业说明、收获和卡点回复“亮点 / 可继续打磨 / 下一步”三行；不读图片内容，可读文字不足时会请成员补充。
- 开启群助教对话后，成员 @ 机器人可讨论作业、AI 工具、项目实操和学习方法，也可进行普通低风险对话；回复机器人上一条消息时可继续上下文。它不声称能实时联网或看过未提供的网页、图片和文件。
- 主动参与模式在明确求助、报错卡住、值得鼓励的小进展，或正在进行且能补充具体价值的作业/项目讨论中考虑接话；跳过纯打卡/复盘/补卡/统计消息，23:00—08:00 不主动说话，默认每群冷却 8 分钟且每小时最多 4 次。聊天线没有改表权限。
- 群成员可发 `@知识库助手 打开打卡表`，机器人只返回当前群对应的多维表格链接，不会串到其他组。
- 每群可用稳定的飞书 `open_id` 配置组长权限。组长可发 `@知识库助手 Arina已完成`、`Arina已补交`或 `Arina未提交`，也可用顿号一次修改多人，如 `卫安、米粒已补交`。“补交/补提交”未写序号时自动归入最近已截止的作业；写 `Arina第2次作业已补交` 则严格修改指定周期。机器人只改指定周期的“人工状态”，同步 SQLite 和多维表格并留存操作审计；普通成员无权代改。
- 写死句式未命中时，MiniMax 可把组长的自然语言（如“第三次那份，卫安和米粒都算补了吧”）解析成受限 JSON。只有置信度达标、名字完全属于本群名单、序号不超过当前作业时才交给确定性代码写表；模型本身没有改表权限。
- 群成员可用 `@知识库助手 补交第2次作业` 或 `@知识库助手 #8月21日 第2次作业已补交` 发起本人补卡核验；身份直接取飞书消息的真实发送人，不要求额外写“我/本人”。机器人只认该发送人的作业链接、图片、文件、话题或完整作业正文，按证据真实时间判定正常/补卡后再写回数据库和多维表格，口头声明不会直接改状态。
- 支持按成员查询全部历史，例如 `@知识库助手 查询小李全部打卡记录`，返回逐次作业、复盘和累计状态。
- 每次生成日报时，会把全员作业/复盘状态和来源消息 ID 写入本地结构化打卡表。
- 同一份状态会自动同步到飞书多维表格，并提供“当前作业周期、本周期已提交、本周期待提交、补卡成员、待迭代、已迭代、本周期已复盘”视图；所有视图都只读取当前周期。
- 打卡表以“作业周期”为主索引，每期包含作业序号和明确起止日期；自然日只用于记录发布、提交和截止时间。
- “周期状态”由机器人自动在“当前周期/历史周期”之间切换，视图固定筛选“当前周期”即可，不再依赖“今天/昨天”。
- 组长可在当期“今日打卡”中直接修改“人工状态”，也可用群命令代改：正常提交、补卡、未提交或不参与统计。人工列由人维护，后续机器人同步不会覆盖。
- “不参与统计”不进入分母、未交名单、催交和群日报；群里不展示该成员姓名、原因或排除人数。
- 课程按独立阶段管理：技术周为 2026-08-17—2026-08-26，共 5 次、每次 2 天，现已结束；视频周从 2026-08-28 开始，每个自然日一次作业，在新阶段内从第 1 次重新编号。
- 视频周每天 08:00 开始当日作业统计窗口，20:00 截止；机器人只用这个时间定义归属，不会凭空生成作业内容。
- 当期截止日 12:00 原生富文本 @ 未交成员，17:00 发送未交名单，20:00 发送最终的已完成/未完成汇总。视频周因为是单日周期，这三个节点每天执行。
- 截止日 20:00 后至次日 12:00 前为补交期；次日 11:00 @ 仍未交成员，12:00 发“正常提交/已补交/仍未交”汇总，12:00 起仍未交记为旷卡。
- 支持为单次作业设置延期截止时间；延期只影响指定作业，截止前仍算正常提交，截止后才算补卡。
- 带日期作业标签的新提交会立即刷新数据库和多维表格，延期截止后的提交自动记为补卡。
- 只有确实写入作业证据的新消息才会获得随机表情回复：周期第一天从送心/碰拳/大笑/比心中选，周期第二天从机智/调皮/了解/击掌/撒花中选，补卡从思考/在做了/惊喜/了解中选；视频周是单日周期，正常提交使用第一天表情池。同一消息只回复一次，不回填历史消息。
- 支持 `@知识库助手 @成员 #迭代 DAY5` 记录待迭代，成员用 `@知识库助手 #迭代 DAY5 已完成` 更新为已迭代。
- 多维表格按成员累计正常提交、补卡和旷卡次数；跨日第一次提交或明确补卡才算补卡，优化版不重复计数。
- 群内发送使用飞书原生 `post` 富文本，标题固定为“进阶营作业群・每日日报”，不会发送 Markdown 源文本。
- 每天 23:00 先刷新多维表格，再向各群发送一条只含核心数字和“今日打卡表”链接的飞书原生富文本简报；不调用 MiniMax 生成长文。
- 群内 @ 查询和“打开日报”仍可随时生成完整日报。
- `SUMMARY_SEND_ENABLED=false` 时不会向群内发送任何信息。
- 直接使用飞书开放 API 和机器人拥有的多维表格，不需要小龙虾/OpenClaw。

技术周已于 2026-08-26 结束：第 1 次 08-17—08-18，第 2 次 08-19—08-20，第 3 次 08-21—08-22，第 4 次 08-23—08-24，第 5 次 08-25—08-26。视频周从 2026-08-28 开始：08-28 是第 1 次，08-29 是第 2 次，以后按自然日递增。视频周结束日尚未配置，确定后应补入 `COURSE_PHASES_JSON`。

## 多维表格模板

仓库已开源可从零复建的脱敏表格设计：

- [`config/base_schema.example.json`](config/base_schema.example.json)：22 个字段、7 个视图、单选选项、筛选、排序和可见字段的机读 Schema。
- [`docs/多维表格设计.md`](docs/多维表格设计.md)：数据分区、人工状态优先级、精确视图规则和从零复建步骤。
- `python3 scripts/validate_base_schema.py`：校验字段、视图和所有引用的一致性。

真实 Base Token、Table ID、群 ID、成员 OpenID 和打卡记录不进入开源仓库。

## 本地运行

```bash
cp .env.example .env
# 填写飞书 App Secret 与 MiniMax API Key；名单或打卡表变化时再覆盖 REPORT_* 配置
python3 -m venv .venv
. .venv/bin/activate
pip install -e '.[dev]'
feishu-group-summary doctor
feishu-group-summary run
```

## 飞书设置

应用需要开启机器人能力、使用长连接订阅 `im.message.receive_v1` 和 `im.chat.member.bot.added_v1`，并拥有读取群消息、获取群成员、以机器人身份发消息和 `im:message.reactions:write_only` 的权限。修改后必须创建版本并发布，再把机器人加入目标群。详见 [飞书后台配置](docs/飞书后台配置.md) 和 [群内首次使用指南](docs/群内首次使用指南.md)。

## 运维命令

```bash
# 检查飞书凭证与总结模型
feishu-group-summary doctor

# 只预览，不发群
feishu-group-summary summary --date 2026-08-11 --chat-id oc_xxx --dry-run

# 手动发送
feishu-group-summary summary --date 2026-08-11 --chat-id oc_xxx

# 只同步结构化打卡记录，不调用模型，也不向群里发消息
feishu-group-summary sync --from-date 2026-08-11 --to-date 2026-08-16 --chat-id oc_xxx

# 只把数据库中已审核的历史状态重新同步到 Base，不重新判定群消息
feishu-group-summary sync --from-date 2026-08-09 --to-date 2026-08-16 --stored-only
```

服务器部署采用 systemd，单元模板位于 [deploy/feishu-group-summary.service](deploy/feishu-group-summary.service)。
