# 飞书后台配置

这个项目使用“自建应用 + 机器人 + 长连接 + OpenAPI”，不使用飞书智能体或小龙虾。

## 必要配置

1. 开启“机器人”能力。
2. 在“事件与回调”中选择“使用长连接接收事件”。
3. 添加“接收消息 v2.0”：`im.message.receive_v1`。只选择长连接但不添加该事件，服务器不会收到消息。
4. 添加“机器人进群”事件：`im.chat.member.bot.added_v1`。该事件用于机器人首次进入已配置新群时自动发送使用指南。
5. 开通“获取群组中所有消息（敏感权限）”：`im:message.group_msg`（后台若展示新版只读权限，则选择对应的 `im:message.group_msg:readonly`）。仅开通 `im:message.group_at_msg:readonly` 时，只能收到群内 @ 机器人的消息。
6. 开通获取群成员列表权限；只有准备向群内发送总结时，才需要以机器人身份发送消息的权限。
7. 创建新版本并发布。
8. 把机器人加入需要总结的群。

如果只开通“接收群内 @ 机器人消息”，机器人无法收集完整群聊；必须允许获取群组中的所有消息。服务器设置 `SUMMARY_SEND_ENABLED=false` 时只收集，不执行定时发送，也不响应群内总结指令。

入群指南有两层保障：优先由 `im.chat.member.bot.added_v1` 立即触发；如果开放平台漏配了该事件，已配置新群的第一条群消息也会触发一次。发送状态存在每群 SQLite 的 `sent_welcome_guides` 表中；服务重启不重发，已有历史消息的群不补发。

## 首次验收

1. 服务日志出现 WebSocket 连接成功。
2. 群里由两个人各发一条普通文字。
3. 再发送 `#总结`。
4. 机器人回复当天群聊总结，并显示正确的消息数和参与人数。
