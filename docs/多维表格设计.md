# 多维表格设计

这份文档是作业统计机器人的脱敏表格设计源文件。仓库中的
[`config/base_schema.example.json`](../config/base_schema.example.json) 是可机读版；本文档说明设计意图和从零复建方法。

真实 Base Token、Table ID、群 ID、成员 OpenID 和打卡记录不属于开源资料。

## 一、数据分区

- 每个群使用独立的 Base/数据表，不共用记录。
- 每人每个作业周期一条记录。
- 特殊缓冲日不生成全员“未提交”记录；跨线或误写序号的提交先按课程内容路由回真实作业周期，再写入表格。
- `记录键` 是主字段，格式为 `周期日期|成员稳定标识`，用于幂等新增或更新。
- `日期` 保存作业周期首日；消息的真实时间分别放在 `提交时间`、`复盘时间` 和 `迭代时间`。
- `周期状态` 只有 `当前周期/历史周期`，机器人负责在周期切换时更新。

| 字段 | 类型 | 选项/格式 | 维护者 |

## 三、人工状态规则

1. `人工状态` 为空：使用机器人根据消息证据计算的状态。
2. 组长选择 `正常提交/补卡/未提交`：该值高于机器人判定。
3. 组长选择 `不参与统计`：该成员不进入分母、未交名单、催交和群日报。
4. 机器人只读取 `人工状态`，不会覆盖组长的值。
5. `当前作业周期` 视图保留所有成员，便于组长恢复状态；其他统计视图排除 `不参与统计`。

## 四、视图筛选

视图都是普通表格视图（`grid`）。不使用 Today/Yesterday，而是依赖机器人更新的 `周期状态`。

| 视图 | 筛选条件 | 默认排序 |
|---|---|---|
| 当前作业周期 | 周期状态包含“当前周期” | 组员姓名升序 |
| 本周期已提交 | 当前周期＋作业状态包含“已提交/补卡”＋排除不参与统计 | 提交时间升序 |
| 本周期待提交 | 当前周期＋作业状态包含“待核验/未提交”＋排除不参与统计 | 组员姓名升序 |
| 补卡成员 | 当前周期＋作业状态为“补卡”＋排除不参与统计 | 提交时间升序 |
| 本周期已复盘 | 当前周期＋复盘状态为“已复盘”＋排除不参与统计 | 复盘时间升序 |
| 待迭代 | 当前周期＋迭代状态为“待迭代”＋排除不参与统计 | 组员姓名升序 |
| 已迭代 | 当前周期＋迭代状态为“已迭代”＋排除不参与统计 | 迭代时间降序 |

机读 Schema 使用飞书 Base 视图的 canonical 结构：

```json
{
  "logic": "and",
  "conditions": [
    ["周期状态", "intersects", ["当前周期"]],
    ["作业状态", "intersects", ["已提交", "补卡"]],
    ["人工状态", "disjoint", ["不参与统计"]]
  ]
}
```

## 五、从零复建

1. 为每个群创建一个独立 Base 或独立数据表。
2. 把第一个主字段重命名为 `记录键`，类型保持文本。
3. 按 `config/base_schema.example.json` 中 `fields` 的顺序创建其余字段。
4. 按 `views` 创建视图，再依次设置 `filter`、`sort` 和 `visible_fields`。
5. 把机器人应用加入 Base，对这张表授予可读写权限。
6. 在 `.env` 或每群私有配置中填写 `BASE_TOKEN`、`BASE_TABLE_ID` 和 `REPORT_LINK`。
7. 执行 `python3 scripts/validate_base_schema.py` 检查开源 Schema，再用 `feishu-group-summary sync` 写入数据。

如果使用 `lark-cli`，字段和视图对应的原子命令为：

```bash
lark-cli base +field-create --as user --base-token '<BASE_TOKEN>' --table-id '<TABLE_ID>' --json '<移除 managed_by 后的 fields 单个字段>'
lark-cli base +view-create --as user --base-token '<BASE_TOKEN>' --table-id '<TABLE_ID>' --json '{"name":"当前作业周期","type":"grid"}'
lark-cli base +view-set-filter --as user --base-token '<BASE_TOKEN>' --table-id '<TABLE_ID>' --view-id '<VIEW_ID>' --json '<view.filter>'
lark-cli base +view-set-sort --as user --base-token '<BASE_TOKEN>' --table-id '<TABLE_ID>' --view-id '<VIEW_ID>' --json '<view.sort>'
lark-cli base +view-set-visible-fields --as user --base-token '<BASE_TOKEN>' --table-id '<TABLE_ID>' --view-id '<VIEW_ID>' --json '{"visible_fields":[...]}'
```

`managed_by` 是本仓库用于说明“机器人维护”或“组长维护”的治理元数据，不是飞书字段创建参数。调用 `field-create` 前要先从单个字段对象中移除它。

这里只使用占位符，不把真实 Token 写进命令历史。

## 六、与代码的一致性

- `service.py::_base_fields_for_attendance` 是机器人写入字段的运行时事实源。
- `service.py::_manual_attendance_overrides` 定义组长人工状态的优先级。
- `config/base_schema.example.json` 定义可公开的表格结构和视图。
- `tests/test_base_schema.py` 保证 Schema 覆盖代码实际使用的字段，并且所有视图只引用已定义字段。
